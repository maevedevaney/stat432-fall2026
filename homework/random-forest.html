Random Forest Analysis

Use only when explicitly asked to fit, tune, evaluate, or report a random forest analysis.

Version 1.0.0

  1. Identify the problem type: Determine whether the task is regression or classification. Identify the response and predictor variables, their types, and the intended prediction target.
  2. Prepare the data: Check for missing values, incorrect variable types, class imbalance, and other data-quality issues. Choose and document appropriate handling; fit learned preprocessing using training data only.
  3. Separate training and test data: Reserve a suitable test set for final evaluation. Do not use it to fit, tune, or select the model. When a separate test set is not appropriate, state the alternative evaluation design.
  4. Fit a baseline random forest: Train an initial forest with default settings where available. Record its configuration and use it as a benchmark for later comparisons.
  5. Tune important parameters: Consider mtry (or the implementation's equivalent, such as max_features) and node size (such as min_samples_leaf). Choose a manageable, data-appropriate set of candidate values and keep other settings fixed unless there is a reason to vary them.
  6. Use appropriate model selection: Select tuning parameters using cross-validation or out-of-bag (OOB) error on training data only. Use consistent folds or resampling across candidates when possible, and never use test-set results to choose a model.
  7. Evaluate model performance: Refit the selected configuration using the training data, then evaluate it on the reserved test set once. Report suitable metrics, such as MSE for regression or misclassification rate and a confusion matrix for classification; distinguish test results from cross-validation or OOB results.
  8. Analyze variable importance: Calculate and interpret variable importance when appropriate. Identify the leading predictors, note that importance is not evidence of causation, and mention limitations such as correlated predictors affecting importance estimates.
  9. Create clear tables and figures: Present candidate settings and their selection results in an organized table. Use clearly labeled figures to communicate tuning results or model performance, and ensure all displays match the computed results.
  10. Write an understandable report: Explain the procedure and findings in straightforward language. Discuss the bias-variance trade-off and relevant limitations, and conclude with the main findings rather than focusing only on technical output. Make code and randomness reproducible, and verify reported values against executable results.
